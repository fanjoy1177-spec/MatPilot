# 从零部署对照协议（实现前口径）

目标：比较从没有 MatterGen 环境，到用户通过 Harness 完成首次真实候选生成、取得可解析 CIF 与报告的完整过程。不预设新流程胜出。

基线归档见 baseline：原材策桌面配置指南、原 dev10 插件入口和固定 MatterGen 官方 README。身份见 identity.json。旧方式仍可在新版插件的手动连接表单中使用。

| 组别 | 流程 |
|---|---|
| A | 固定版官方文档人工安装，再人工接入材策/Harness |
| B | 同一 Harness/模型，普通部署提示词辅助安装，允许正常查阅资料 |
| C | 材策部署工具，固定配方、下载校验、任务恢复、分层验证与自动接入 |

若声称 LLM 在确定性安装器之上有额外收益，另加仅运行安装 CLI 的组别。系统故障注入测试只证明控制逻辑，不替代用户完成率。

各组使用相同硬件和干净快照。分别报告无下载缓存和已有缓存，保持网络/版本/模型权重相同，轮换操作顺序，记录操作者经验，避免先做 A 后熟悉流程造成 C 偏差。共用修正后的上游兼容组合，不故意让基线使用已知损坏的依赖版本。

至少覆盖：无 Python/模型但系统前置条件满足；缺少 WSL/驱动；下载中断；损坏下载；已装不兼容环境；重启或后台进程退出后恢复。无适用 GPU 的正确诊断单独计分，不计作本地生成成功。

每个运行记录原始事件、阶段耗时、总时间、人工主动操作时间、人工操作次数、求助、首次任务完成、故障与恢复、下载量、API/算力费用、CIF/报告身份。安装检测、MCP连接与真实生成分别评分。未测字段填 null；失败与退出保留在分母，费用包含失败重试。

本轮工程开发不会代填用户主动时间、独立用户样本或提速比例。发布时间只能报告实际完成的安装/验证和故障恢复证据。对照检验有效性，不单独证明首创。
