## 补充的真实 AI 场景

模型为 deepseek-flash，关闭思考模式，后端锁定 demo。六个提示各运行一轮，共27次 API 调用，完整失败、修正和最终回答保留在 [补充联调记录](../artifacts/v04-live-acceptance.json)。

| 场景 | 观察到的行为 | 限制 |
|---|---|---|
| 元素体系与未评价析氧、耐氯目标 | 计划就绪，保留目标，未编造数值或执行 | 需求中仍混入一条流程说明，未独立评分 |
| 固定 LiFePO4，缺少模板与对称性 | 拒绝启动，未换成元素集合 | 提议的“未提供”字段无效，被源文校验拦截；解释中个别表述过于笼统 |
| 带隙硬下界，缺少评价器 | 保留下界，阻塞；不改成生成目标 | 未实际验证性质 |
| Fe-O 加凸包能引导目标50 meV/atom | 首次因后验目标文本不一致被拦截，修正后两个条件同时保留，换算0.05 eV/atom | 不等于稳定性或可合成性证据 |
| 最多2次却要求3个合格候选 | 明确拒绝，不增加预算 | 未执行 |
| 希望2个去重候选、最多2次 | 首次遗漏执行参数被拦截，修正并确认后执行；如实报告2个文件、1个独立结构、目标未达到；没有补采 | 固定软件样本，不是真实生成 |

这说明插件能在这些开发场景中拦截错误、支持修正和如实呈现数量；不能外推为通用正确率、AI增益或提速比例。此前三场景的修复前失败与复测见 [上一阶段记录](release_acceptance_v02.md)。
