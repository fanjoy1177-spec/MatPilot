# 插件对任务质量和流程效率的作用

MatPilot 的具体价值是把需求和候选检查变成可调用、可追溯的程序步骤。已有开发对照显示部分任务减少往返，但全量结果尚未证明整体提速。作品展示同时呈现检查收益、额外步骤和失败，避免把“接入 AI”本身当成创新证据。

## 现有对照能说明什么

| 用户负担 / 错误来源 | 插件提供的功能 | 实际对比证据 | 结论边界 |
|---|---|---|---|
| 逐个读取候选，容易把数量等同于合格数量 | 集中做组成检查、结构去重和逐项汇总 | r3 D0101：三组各采样4次；M返回3个有效、1个唯一有效候选，用8次工具；U/U+各18次 | 该题减少查询往返，有核验依据；不是整体提速率 |
| CIF导出标签与坐标对称性可能不同 | 从坐标重新检查空间群，保留容差和方法 | r3 D0401：M检查得到221；U/U+主要依赖P1文件标签 | 证明该固定结构的检查作用，不证明材料稳定 |
| 不同评价方法的数值被直接排名 | 绑定候选/版本/方法，显式返回不可比 | r3 D0502：三组都没有错误排名；M提供可审计的不可比判定 | 共同成功不能当成插件独有正确性优势 |
| 需求翻译后丢条件或添条件 | 原文锚点、逐项映射、完整组合校验 | r3 D0202：M提出无依据模板/条件后被程序阻塞；D0402保留冲突条件 | 显示程序能拦截具体错误，也显示LLM会提出错误计划 |
| 故障后有效产物丢失、预算不清 | 独立保存有效候选，保留失败及已启动尝试 | dev5→dev6相同CPU夹具：短返回保留0→1，好坏CIF混合0→1，报错但完整归档0→2 | 是生产流程可靠性改进，不计作AI理解提升 |
| 修改建议过于笼统，用户仍需猜参数 | 列出需求ID、条件和检查方式前后差异，预算不变 | dev6单元验证保留数值目标及硬结果要求，修订形成新计划 | 尚未测人工纠错时间，不能填提速比例 |

r3 全12题：M/U+工具调用为94/104，墙钟合计159.031/133.756秒，API核算2.842496/2.298286元。M工具次数较少，但耗时和费用更高。全部36条对话正常结束不等于36题答对；未独立评分，人工主动时间未测。逐题数据及不利案例见[完整对照](study_plugin_effects.md)。

四题消融进一步区分模块作用：关闭结果核验后接口明确返回未检查，完整插件提供有效/唯一数量和方法可比性判断；LLM仍能读取原始证据并自行判断。三臂费用、耗时和失败均见[消融记录](study_ablation_results.md)。需求映射的独立收益尚不能据此确定。

[修复前后原始数据](../artifacts/v06-partial-output-comparison.json)记录冻结旧版、输入和源码哈希；[复算脚本](../benchmarks/compare_partial_outputs.py)不调用API。三例请求和采样扣额均为2，新版仍标partial、额度耗尽后仍拒绝恢复，不以多保留文件换取虚假的成功状态。

## 开发过程中如何留下可用证据

每项修改按“问题 → 相同输入 → 修改前后行为 → 验证记录 → 尚未证明的收益”记录。版本修复比较与U/U+/M系统比较分开，避免把通用缺陷修补当成AI独有贡献。相同预算不保证相同工作量，展示耗时前同时给出实际采样和已完成检查。

| 指标 | 记录方式 | 当前是否有可用结果 |
|---|---|---|
| 工具/LLM往返与费用 | 全量轨迹、失败调用、统一账本，按题配对 | 开发题已有；正式新题未运行 |
| 墙钟时间 | 每条运行开始至结束，含API及宿主开销 | 开发题已有；不是人工时间或GPU速度 |
| 完整任务正确率 | 需求、动作、候选身份、结论四项都通过 | 未独立评分，保持未评 |
| 人工步骤、主动用时、首次可完成时间 | 实际用户操作记录，统一任务与起始环境 | 未测，不以工具次数代替 |
| 无效启动、误拒绝、无依据结论 | 保留全部计划和输出，结合题目标准审核 | 有待审案例，未形成正式比例 |
| 故障后保留数量与预算 | 同一CPU替身产物、冻结版本和固定断言 | 可作软件可靠性证据，不能当成材料效果 |

## 可用于作品说明的表述

> MatPilot利用现有Harness与材料模型，把用户要求连接到可检查的计划和候选证据。开发对照中，插件在部分候选筛选任务减少了查询步骤，并给出可追溯的检查依据；它也增加了规划和核验开销，当前尚未证明整体提速。项目的可交付贡献是可复用的需求保持、候选核验和故障结果保留机制，效果以公开的逐题记录为依据。

后续由用户统一审核已有记录并提出修改；当前不安排老师做题，也不追加真实材料计算。只有实际测得人工时间和正确完成率后，才添加对应改善数字。
