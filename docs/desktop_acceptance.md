# 桌面与真实 API 开发验收

验收于 2026-10-21 晚完成，0.1.1 于次日整理。本记录证明工具可由真实 AI 调用并完成演示流程，不是用户效率实验，也不是材料性能验证。

## 环境与范围

- 宿主：已打开的 DeepSeek Harness Desktop 0.2.1-rc.2。
- 大模型：官方 DeepSeek API，deepseek-flash，测试会话关闭推理模式，单次输出最多 2048 tokens。
- 工具：Harness 内置 MCP 客户端连接本地 MatPilot；九个工具注册成功。
- 后端：锁定 demo，最多 4 个样本，执行命令设置为不可用占位符；只有固定 NaCl 数据和轻量结构检查。
- 验收会话只允许调用 MatPilot 工具。未运行 MatterGen 推理、DFT、弛豫或其他科学计算。
- 通过宿主的会话和工具机制自动驱动测试，未逐个验证界面按钮、移动端界面或远程服务器。

## 六类案例的最终检查

| 案例 | 检查内容 | 最终观察 |
|---|---|---|
| 明确需求 | Fe-Ni-O、4 个、每批 2 个、种子 42；保留两个后验目标 | 方案 ready，参数保留，未擅自提交 |
| 联合条件冲突 | Fe-Ni-O 与带隙目标 2 eV 同时要求 | 两条件都保留，返回 incompatible_conditions，没有偷偷删除条件 |
| 固定化学式 | 精确 LiFePO4，禁止放宽成元素集合 | 明确说明当前不支持，没有改成 Li-Fe-P-O 执行 |
| 单位换算 | 1200 meV 带隙目标 | 保存为 1.2 eV，不当作测量值或保证区间 |
| 定性科研目标 | 析氧活性、耐氯腐蚀性，用户未给数值 | 保留为 review_targets，不编造指标，不为可选参数强行阻塞 |
| 演示闭环 | 两个固定 NaCl 样本，分批检查和出报告 | 方案、确认、提交、查询、筛选、报告及最终回答完成；识别文件重复并注明示例来源 |

这些是用于开发和修正提示的案例。重复测试使用了相同题目，不能据此给出泛化成功率、获奖概率或用户提速百分比。最终示例产生两个文件，其中一个是精确文件重复；不把它们算成两个新材料。

## 保留的失败与修正

共记录 11 次案例运行（含试跑、复测和中断）。公开的 [精简原始记录](../artifacts/desktop-acceptance.json) 保留每次工具调用、回答与费用条目；本机完整事件记录另外留存。

1. 初次明确需求把元素体系传成数组，工具拒绝后模型自行修正。随后补充了正确输入格式和示例。
2. 定性目标曾引发无必要的澄清。随后补充“后验目标不自动阻塞”和“不要追加未请求的可选数值”规则，复测符合预期。
3. 验收模块曾读取错误的参数字段，误拒绝了已确认的演示提交；这是测试驱动缺陷。失败对话还暴露了用 plan_id 查询 job_id 的错误，已补充规则。
4. 一次演示已生成报告，但测试器的 8 次 API 调用上限阻止了最终回答。调整为 12 次后复测。
5. 一次对话在配置重新加载期间中断，没有完整用量；保留该调用的费用预留。待配置稳定后复测完成。

工具规则能校验收到的结构化参数，尚不能保证找出模型提取阶段的所有需求遗漏。保留原文与审阅方案仍然必要。

## 费用与停止状态

测试共发起 45 次 API 请求，44 次返回完整用量。按输入全部未命中缓存、全时段使用高峰价计算：

- 已返回用量的费用上界估计：0.411448 元。
- 1 次中断请求的完整上下文及最大输出预留：2.113536 元。
- 合计预算占用上界：2.524984 元，低于用户要求的 20 元。

估算采用验收当日核实的 deepseek-flash 高峰费率：输入 2 元/百万 tokens，输出 8 元/百万 tokens。它不是账户账单；缓存命中和优惠时段可能使实际金额更低。价格依据见 [DeepSeek 官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

验收模块内部限额为 19 元，发起每次调用前先预留整段最大上下文和输出费用；中断且没有完整用量的请求不释放预留。该限额只约束验收模块自己的会话，不约束用户随后手动发起的其他对话。

付费测试完成后已停用临时验收模块。正式保留的 MatPilot 演示服务报告版本 0.1.1、后端 demo；通过不调用大模型的能力查询再次核验九个工具。API 验收期间的旧进程仍报告 0.1.0，记录保留这一事实，没有回填版本号。

## 下一步如何证明提升

先冻结本版，在独立题目和受试者上比较官方操作流程、结构化入口、AI 插件三种方式。记录正确完成率、约束遗漏、误执行、人工时间、求助次数与每个正确任务的费用。只有这一对照完成后，才写“提速多少”或“AI 比规则入口提高多少”。详见 [验证方案](validation_protocol.md)。
