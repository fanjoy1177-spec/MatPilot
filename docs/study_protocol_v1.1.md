# 任务改进与流程效率评估执行说明

这套框架用于检验提升，不预设 MatPilot 胜出。当前已有任务草案、基线补丁和统计程序；尚无正式对照结果，不填入推测的提速比例。

## 分离开发和正式评价

benchmarks/study/development_tasks.json 包含 12 道开发题；test_candidates.draft.json 包含 36 道候选测试题，六类各六题，其中 9 道标为跨模型、18 道标为初始可执行。数量检查不证明领域标注正确。草案由开发过程编写并看过，尚未成为未见过的正式封存测试；材料复核者应替换重叠题、核对实际可执行性并补齐回放情境。

正式封存前需真实材料相关人员复核必要要求、允许动作、固定澄清回复、候选身份和结论边界。复核文件必须绑定完整题库 SHA256，记录复核人、资格、日期与意见。软件只能保存此声明，不能替代或认证人工独立性。标准答案不可提供给运行中的 LLM；开发题、候选草案和正式题的存储路径应分离。

使用 python -m matpilot.evaluation audit benchmarks/study/test_candidates.draft.json --formal 检查结构与配额。freeze 命令需要实际复核 JSON；不要用测试中的虚构复核人填充正式记录。

## 公平基线

U 使用固定上游及正常技能文档；U+ 加 benchmarks/baseline/atomisticskills-uplus.patch；M 共享 U+ 的同等科学能力和局部修复，再加 MatPilot 检查层。补丁原始文件快照、哈希和许可证随仓库保存，原参考目录未修改。

四项修复：条件同时保留或显式拒绝；3 次采样按 2+1 执行；同化学式目标按唯一候选 ID 选择；数据库查询失败显示未知。已做隔离替身回归，未完成上游实际模型/Harness 基线端到端验收；不能据此声称 U+ 已经就绪。

三组环境清单必须固定相同宿主、LLM、推理模式、科学能力、回放数据、澄清规则、轮数/输出/采样预算。调度程序拒绝条件不一致及 U+/M 补丁不一致。可用模型或检查器有差异时先修正实验设计，不直接比较。不要为了保持 M 优势限制基线查文档或正常工具能力。

正式计划每组每题 3 次，主实验 324 次；预先随机化组别顺序。两项消融使用事先指定子集，分别移除映射和结果核验，必须单独验证驱动行为，不能仅改组名。当前尚未实现和验收完整三组 Harness 驱动与审定回放夹具；环境模板的 driver_validated=false 保持原样。

## 记录与评分

每次运行保留不可覆盖的原始轨迹、配置哈希、完成/失败/超时/预算停止原因、墙钟时间、人工主动操作时间、API 和科学计算成本。未测的人工时间保持 null，不能用运行时间代替。API 调用沿用本项目总预算，不新开计费账本绕过 20 元上限。

record_run 保存轨迹哈希；blind_packet 隐去组别标签，评分结果绑定同一轨迹。工具行为可能让评分者猜到组别，应披露只能部分盲法。四项主评分均通过才算完整正确：需求、动作、候选身份、结论证据。另记可执行题完成、误拒绝、遗漏、错误启动和无依据结论。

summarize 保留全部计划运行作为分母；未完成/未评分时明确标为不可解释效果，不输出配对收益。正式分析以题目为聚类单位，三次重复先在题内汇总，再计算 M-U+ 配对差异与 bootstrap 区间。失败调用成本也计入每个正确任务成本；缺少人工时间时不输出人工提速。

开发题单位测试中人为构造的分数只用于检查统计程序，绝不能拿它们当成实验效果。实际全部原始记录和外部评分齐备后，才能应用方案 v1.1 中的投入判断线。
