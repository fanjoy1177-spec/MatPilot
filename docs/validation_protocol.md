# 插件任务提升与流程提速验证方案

## 需要检验的结论

MatPilot 的待验证主张是减少从材料需求到可执行任务、再到可追溯结果所需的人工工作，并减少不兼容条件导致的返工。GPU 生成速度与人工操作速度分别报告。插件没有修改 MatterGen 网络或采样器，不能据此声称单次材料生成计算更快。

## 两组对照

工程流程对照：官方命令行配合原始输出目录，对比使用相同模型、条件、批次、硬件的 MatPilot 完整工具流程。用户均可查阅各自文档，统一培训时间；安装准备时间独立统计。以首次正确提交所需人工时间、结果整理所需人工时间、步骤数、错误提交数和成功恢复率评价工程封装。

AI 对照：A 为结构化任务模板与规则检查；B 为一次大模型解析加相同规则后端；C 为同一个大模型通过 Harness 查询能力、接收校验反馈并修订计划。A 不需要开发独立界面。B 与 C 使用同一模型版本、温度和条件字典；不要将后端修复只提供给 C。C 的有限工具回合上限预先固定为 6，不能无限试错。

任务分六类：明确条件、单位变化、定性或缺失要求、条件组合冲突、模型不支持的研究目标、故障恢复。正式实验前准备 12 条开发题和 36 条封存题。第一版只评价 MatterGen，新增模型后另建跨模型测试，不能把一个模型的多个检查点称为多个模型。

## 记录口径

| 指标 | 定义 |
|---|---|
| 计划正确率 | 人工独立核对原始需求、完整参数和后验目标，语义全部符合才算正确 |
| 首次正确提交耗时 | 从用户读到任务到首次提交正确且可执行方案的人工活跃时间 |
| 结果整理耗时 | 从生成文件可用到形成完整可核验报告的人工活跃时间 |
| 错误提交率 | 不兼容、遗漏硬约束或误改目标仍进入执行的比例 |
| 人工干预次数 | 用户改参数、解释报错、补充缺失条件、手动整理结果的次数 |
| 计算耗时 | 后端任务实际开始到明确结束的时间，与排队时间分别记录 |
| 大模型成本 | 输入输出 token、调用次数和账单金额；缺失账单时不估称实付 |
| 恢复完整率 | 故障恢复后文件数量及哈希一致性，且无重复计算已完成批次 |

提速百分比 = (基线人工时间 - 插件人工时间) / 基线人工时间 × 100%。同时报告原始分钟数、样本量、中位数与分布，不能只挑选最快示例。失败任务不从分母剔除，单独报告超时和失败耗时。

B、C 每题各运行 3 次；重复运行属于同一任务内的重复，不当作额外独立样本。用户测试建议 6 人，每人 6 题，A/B/C 各 2 题，使用等难度题并轮换顺序，避免对同一题熟悉带来的优势。样本较小，结果只作探索性证据。

## 内部决策标准

C 计划正确率目标至少 90%；相比 B，复杂任务正确率增加至少 15 个百分点，或人工干预减少至少 30% 且正确率不下降。相比 A，人工操作时间目标减少至少 30% 且正确率不下降。这些均为预定目标，尚非实测成果，也不是获奖承诺。若 AI 没有稳定额外收益，作品以能力校验、执行管理和报告自动化为主要贡献。

## 当前证据边界

单元测试证明限定输入下的软件行为。协议测试证明工具能被发现和调用。历史真实生成联调证明执行链可运行。0.1.1 已通过真实 DeepSeek API 的六类开发验收，使用固定演示后端，没有进行新的真实材料计算；具体过程和失败记录见 desktop_acceptance.md。

上述证据均不能代替自然语言语义准确性对照和外部用户计时。开发验收中的 12 次 API 请求上限用于调试，不是此处预注册的正式对照回合数；正式实验前应单独冻结预算、轮次和题目，再执行 A/B/C 对照。
