# 材策 MatPilot 第一版架构

用户在 DeepSeek Harness 自带界面提出需求。Harness 中的大模型读取 MCP 服务公开的模型能力，调用 prepare_plan，将完整条件交给确定性校验器。可执行方案获用户授权后进入持久化作业库，由独立进程执行 MatterGen。任务不依赖一次对话连接保持在线。

```mermaid
flowchart LR
  U[用户材料需求] --> H[Harness 现有界面与大模型]
  H --> M[MatPilot MCP 九个工具]
  M --> V[模型能力与条件校验]
  V --> P[固定方案与任务库]
  P --> W[独立批次执行进程]
  W --> G[MatterGen 环境]
  G --> C[CIF 解析与基础检查]
  C --> R[报告与证据记录]
  R --> H
```

## 第一版范围

只接入 MatterGen 一类模型。其多个检查点是同一模型的不同条件能力，不计为多模型支持。通过 ModelAdapter 接口与 ADAPTERS 注册表预留后续模型接入；第二个真实模型验证前，不宣称跨模型兼容已经实现。

MCP 连接采用 stdio。本地使用本机 Python，远程部署可由 Harness 的 MCP 客户端通过 SSH 启动服务器上的 MatPilot。没有公开无鉴权 HTTP 执行服务，也不向所有用户提供免费算力。Windows WSL 后端由 Linux 监督进程负责停止整个计算进程组，避免只关闭 wsl.exe 后遗留 GPU 任务。

## 可复用与改进

沿用 MG-Flow 中 MatterGen 条件字典、命令参数数组、分批运行和候选结果与后验目标分离的设计。第一版独立打包，避免把旧项目的本机路径、历史数据和实验依赖作为安装前提。

重新实现完整条件匹配、方案哈希、幂等提交、SQLite 作业管理和逐批输出校验。使用 pymatgen 的原子位点解析元素，避免从 CIF 标题或 P1 空间群字符串误读出元素。仅文件哈希去重，不把文件不同等同于晶体学新颖。

## 已知限制

本版本未提供工作进程意外崩溃后的自动接管。心跳延迟只给出诊断，不自行判定终止或重启；管理员需核对真实计算进程，避免重复执行。数值条件是采样目标，生成结果未必满足。原始自然语言是否被准确转成结构化条件仍需模型语义评测，规则校验无法发现所有语义遗漏。
