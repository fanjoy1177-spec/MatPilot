# 材策 MatPilot 同类作品与开发复用调研

后续修订：补查发现 AtomisticSkills 是更接近的插件化对照，第二模型选型与主实验安排已调整。当前开发决策以 [AtomisticSkills 深度复用分析](AtomisticSkills_深度复用分析_2026-10-21.md) 和 [MatPilot 研发方案 v1.1](MatPilot_研发方案_v1.1_2026-10-21.md) 为准；下文保留首轮调研记录。

检索日期：2026 年 10 月 21 日。

本调研以本地《材策 MatPilot 多模型材料研究智能体插件研发任务书 v1.0》为范围：DeepSeek Harness 负责对话与规划，MatPilot 提供材料能力目录、规则校验、模型适配、后台任务与证据报告；MatterGen 是首模型，第二模型候选为 Chemeleon 和 CrystalFormer。MG-Flow 是可复用后端，不是本次调研对象的完整定义。

结论：已有多项相近研究和可直接采用的工具。建议复用官方模型、科学计算库、MCP 实现和现成查询服务，把自主开发集中于跨模型能力匹配、需求完整性、执行状态和证据可追溯。以下接入优先级是结合任务书作出的工程判断，并非已经完成兼容性或性能测试。

本轮进行了论文、作者仓库、官方文档检索，并只读检查了本地任务书及部分代码。没有安装这些外部项目，没有运行模型、测试 API 密钥或证明 GPU 环境可用。

## 一 同类作品与重合范围

| 作品 | 已公开的相关能力 | 对 MatPilot 的价值 | 建议用法与限制 |
|---|---|---|---|
| [Material Agent](https://github.com/Guichena/material-agent) | 自然语言解析、MatterGen/DiffCSP 生成、MatterSim/Comformer 评估及报告 | 与“需求到结构到评估到报告”的主流程高度重合 | 优先研究独立环境适配器和输出对象；作为同类系统对照。README 写有自动回退，接入时必须明确记录实际后端与语义变化。README 声明 MIT，实际取用文件及内含模型应分别核验许可。 |
| [ChemGraph](https://github.com/argonne-lcf/ChemGraph) | 自然语言计算工作流，基于 LangGraph、ASE 等；具有 CLI、Python、网页及 MCP 入口 | 工具组织、会话记录、计算结果返回及科研任务案例 | 适合挑选工具或作为独立基线。已有 Harness 时，整体迁移到其智能体框架会引入额外集成工作。仓库标注 Apache-2.0。 |
| [MatSciAgent](https://www.nature.com/articles/s43246-025-00994-x) | 数据检索、晶体生成、连续介质与分子动力学任务，由主智能体分派 | 为“按任务路由到材料工具”提供直接相关工作 | 用于论文综述及任务分类设计；论文能力不代表本机可直接部署。[作者代码](https://github.com/cakshat/MatSci-LLM-Agents) |
| [ChatMat](https://github.com/Xiaobu-USTC/ChatMat) | 材料数据查询、计算方案设计、DFT 与机器学习势工作流 | 多步骤计划与计算反馈的参考 | 优先阅读任务定义和评价方式。本次仓库页面未确认明确许可证，先作为研究参考。[论文](https://doi.org/10.1039/D5DD00582E) |
| [LLaMP](https://github.com/chiang-yuan/llamp) | 通过 Materials Project 数据支撑材料问答和工具调用，提供网页与 Python 接口 | “每条结论有数据库依据”的参考 | 简单查库先采用官方 MP 接口；需要更复杂检索研究时再评估整个系统。 |
| [SparksMatter](https://github.com/lamm-mit/SparksMatter) | 无机材料研究中的规划、计算、迭代审视与报告 | 研究计划和证据反馈的相关工作 | 用于比较研究思路；作者报告的评分或案例效果不能直接转为我们项目的效果。仓库标注 Apache-2.0。 |
| [LLMatDesign](https://github.com/Fung-Lab/LLMatDesign) | LLM 驱动的材料设计，仓库依赖 MatDeepLearn | 生成与性质反馈结合的研究参考 | 后续做闭环优化时再考虑，首版不必增加这一整套依赖。仓库标注 MIT。 |

这些项目说明，自然语言入口、多个材料工具和自动报告均已有先例。MatPilot 的差异应落实为可测试的行为，例如不丢弃条件、正确区分任务类型、识别无法满足的条件组合、准确返回部分完成状态，以及在相同后端下减少人工干预。是否形成有效研究贡献仍由对照结果决定。

## 二 已经能够省下的开发工作

| 需求 | 优先采用的现成方案 | MatPilot 仍需完成的工作 | 优先级 |
|---|---|---|---|
| 多轮对话与外部工具调用 | [DeepSeek Harness MCP 客户端](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md) | 工具描述、材料领域提示、配置与调用轨迹关联 | 首版直接复用 |
| MCP 协议和工具参数描述 | [官方 MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) | 用九个稳定工具封装领域服务；保存结构化错误和结果 | 首版直接复用 |
| MatterGen 生成 | [官方 MatterGen](https://github.com/microsoft/mattergen) 与现有 MG-Flow 执行经验 | 能力目录、准确参数映射、预算、队列、实际产物检查 | 首版直接复用 |
| 第二模型与已有工具封装 | [Chemeleon](https://github.com/hspark1212/chemeleon)、[CrystalFormer MCP](https://github.com/deepmodeling/CrystalFormer/blob/main/mcp/README.md) | 隔离环境、输入语义、任务对象与结果对象适配 | 首版选一个验证 |
| CIF 读取和结构比较 | [pymatgen](https://pymatgen.org/) 的结构对象、CIF 解析和 StructureMatcher | 明确几何阈值、去重容差与适用范围；记录方法版本 | 首版直接复用 |
| 材料数据库检索 | [Materials Project 官方 MCP](https://docs.materialsproject.org/services/ml-and-ai-applications/mcp) 或 [mp-api](https://docs.materialsproject.org/downloading-data/using-the-api/getting-started) | API key 配置、缓存、来源 ID、查询时间与返回字段保存 | 低成本扩展候选 |
| 结构三维展示 | [3Dmol.js](https://3dmol.org/)，已有 [CIF 解析接口](https://3dmol.org/doc/global.html#CIF) | 在结果页关联 candidate_id、结构文件和指标 | 展示阶段采用 |
| 势能、力和结构弛豫 | [MatterSim](https://github.com/microsoft/mattersim) 配合 ASE 计算接口 | 适用域、收敛条件、失败状态和结果单位 | 生成链路完成后接入 |
| 较复杂科学计算工作流 | [jobflow](https://materialsproject.github.io/jobflow/) 与 [atomate2](https://materialsproject.github.io/atomate2/) | 将具体计算步骤映射为 Job/Flow；选择实际支持的计算软件 | 后续按需求引入 |
| 其他科研 MCP 工具 | [AI4S-agent-tools](https://github.com/deepmodeling/AI4S-agent-tools) 和 [ABACUS-agent-tools](https://github.com/deepmodeling/ABACUS-agent-tools) | 按任务选择单个工具、核验依赖与许可、映射证据对象 | 首版以阅读和接口参考为主 |

“直接复用”指采用已有实现，不表示无需配置或测试。队列基础设施可以复用，但 MatPilot 的计划版本、幂等提交、预算和完成状态语义仍由本项目负责。

当前首版是小规模本地任务，任务书已经选择 SQLite 和后台执行进程。建议先完成这一方案；出现远程集群、多节点或复杂依赖图需求时，再评估 jobflow/远程执行管理器，避免同时维护两套任务真相。

## 三 最值得立即纳入选型的三个发现

### CrystalFormer 已有 MCP 服务

官方 `mcp/README.md` 提供 `generate_structures`，输入包含确定化学式，输出包含执行信息、输出目录和候选 CIF。还需要模型权重、弛豫模型和凸包数据等配置。这可以节省底层调用与后处理封装工作，但并不等于现成的 MatPilot 异步任务服务。[接口说明](https://github.com/deepmodeling/CrystalFormer/blob/main/mcp/README.md)

建议将 CrystalFormer 从普通备选提升为与 Chemeleon 同级的短期选型候选：如果目标是验证“元素体系生成”和“固定化学式结构预测”的跨任务路由，其输入差异有研究价值；如果现有 PyTorch 环境和文本生成案例更容易复现，Chemeleon 仍可能更合适。CrystalFormer 的 JAX 环境与 GPU 配置也要计入成本。[模型说明](https://github.com/deepmodeling/CrystalFormer)

不要将官方长时间生成工具直接放进聊天请求并一直等待。推荐由 MatPilot 先校验和排队，worker 调用底层模型流程，工具调用立即返回 job_id。这样也保留统一预算、停止和结果收集机制。

### Materials Project 已有官方 MCP

官方文档明确说明 `search` 和 `fetch`：可按化学式、元素体系或关键词检索，再获取详细材料信息。文档同时列有开发中的工具，不能把这些计划项当成已验证能力。[官方文档](https://docs.materialsproject.org/services/ml-and-ai-applications/mcp)

我们可以先用于已知材料参照和有来源的研究上下文。数据库条目是已有材料的记录，不是新生成候选的实测属性；需要将数据库 ID 和生成候选 ID 分开。需要批量检索或严格控制返回字段时，可直接用 mp-api，仍无需自行爬取网站。[API 入门](https://docs.materialsproject.org/downloading-data/using-the-api/getting-started)

### DeepModeling 已有可组合科研工具

AI4S-agent-tools 列出的当前工具包括 DPA 原子模拟、CALYPSO 热电筛选、ABACUS、文献检索等，按独立 MCP 服务组织。其页面另有 Coming Soon 部分，不能据此承诺已有光谱分析、三维展示或实验优化工具。[工具集合](https://github.com/deepmodeling/AI4S-agent-tools)

建议优先参考服务模板、工具能力描述和独立环境组织。ABACUS-agent-tools 适合未来接入第一性原理计算时评估，依赖计算软件、赝势等外部资源，不能仅安装 MCP 包就认为 DFT 已接通。[ABACUS 工具说明](https://github.com/deepmodeling/ABACUS-agent-tools)

## 四 对现有开发计划的具体补充

本轮只读检查确认，MatPilot 已有 MatterGen 能力与条件校验代码、任务服务和结构检查；`structures.py` 已使用 pymatgen 的 `CifParser`，不能把 MG-Flow 旧版全文扫描元素的问题误报成 MatPilot 当前仍采用的实现。是否完整接通九个工具及真实模型，需要独立验收。

| 任务书条目 | 建议补充 | 验收方法 |
|---|---|---|
| T01 能力规范 | 从官方 README、模型卡和固定版本提取规则；区别元素体系、确定化学式、文本描述、目标值和硬约束 | 每条能力限制附来源、版本和核验日期；冲突不得静默舍弃 |
| T02 可靠执行 | 复用现有批处理实现，所有模型进入同一计划和任务状态机制 | 停止、续跑、失败、重复提交都有可复核记录；外部服务成功响应不替代产物检查 |
| T03 结果筛选 | 在现有 pymatgen 解析上补结构等价去重；选用现成结构对象与算法 | 同结构不同文本仍能识别；参数和适用范围随结果保存；几何检查只标为基本检查 |
| T04 证据报告 | 复用现有报告生成逻辑，补模型权重、原始文件校验值、评价方法和数据库来源 | 任一关键表格行能回到实际文件或来源记录；不同方法算出的指标不混排 |
| T05 智能体接入 | 官方 SDK 负责协议，Harness 负责对话；领域服务处理规则和执行 | 不在 prepare_plan 内再次调用另一套 LLM；错误返回可供澄清或修正 |
| T06 第二模型 | Chemeleon 与 CrystalFormer 使用同一份选型检查表 | 分别记录安装成功、权重就绪、真实小任务、可解析 CIF、语义匹配和接入改动量 |
| T07 对照研究 | 保留 A 表单、B 单次解析、C 多轮工具协作；另设一个相近项目或官方 MCP 演示作为外部参照 | A/B/C 保持后端等价；外部参照只比较共同任务，不混作纯 AI 增益 |

自主开发建议保留四项：完整需求到可执行条件的映射；跨模型能力匹配；统一任务与证据对象；冻结任务集和评分标准。每项均对应可观察结果，不能仅凭模块存在宣称有效。

## 五 接入前已发现的版本与许可问题

1. **MCP Python SDK 的主分支和当前项目依赖不是同一代。** 本地 `pyproject.toml` 为 `mcp>=1.20,<2`；官方当前主分支文档介绍 v2，并将高层服务类从 FastMCP 改为 MCPServer。建议本轮固定兼容版本并阅读对应分支文档；升级应单独安排。[SDK 说明](https://github.com/modelcontextprotocol/python-sdk)、[迁移说明](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/migration.md)、[v1 分支](https://github.com/modelcontextprotocol/python-sdk/tree/v1.x)
2. **第三方 `fastmcp` 包与官方 SDK 中的旧 `mcp.server.fastmcp` 不应只凭同名认作相同依赖。** CrystalFormer 文档使用前者。可以用独立环境隔离，通过协议交互，但仍需做客户端与服务端兼容测试。[CrystalFormer 配置](https://github.com/deepmodeling/CrystalFormer/blob/main/mcp/README.md)
3. **长计算与 MCP 调用时限要分离。** Harness 当前客户端文档给出默认每次调用 60 秒的时限，不能用它代表科学计算可以持续多久。[Harness 客户端](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md)
4. **研究仓库的许可声明可能不一致。** AI4S-agent-tools 的 README 写 Apache-2.0，而 GitHub 页面识别 LICENSE 为 MIT。采用前应冻结提交并逐项核验实际 LICENSE 及子模块；不能把根目录说明自动套到所有工具。[README](https://github.com/deepmodeling/AI4S-agent-tools)、[LICENSE](https://github.com/deepmodeling/AI4S-agent-tools/blob/main/LICENSE)
5. **代码、模型权重、数据库和计算软件分别核验。** 例如 ABACUS-agent-tools 页面标注 LGPL-3.0；ChatMat 本次页面未确认许可；Material Agent 的 README 声明 MIT 也不覆盖其所有外部模型。此处是依赖选型记录，不构成对全部分发方式的法律判断。

## 七 命名与近期落地顺序

公开资料中已有 2024 年提交的同名材料研究论文 *MatPilot: an LLM-enabled AI Materials Scientist under the Framework of Human-Machine Collaboration*，其主题同样涉及自然语言、人机协作和材料智能体。本次没有确认该论文作者提供可直接部署的公开代码。[原论文](https://arxiv.org/abs/2411.08063)

另有 [MatPilot 材料表征网站](https://www.matpilot.site/) 和 [矩池云 MatPilot 科研工作台](https://matpilot.matpool.com/)。这些名称存在于不同项目中，不应把其功能、成熟度或代码归属混合。建议在正式参赛材料和公开仓库定名之前调整英文名称，中文“材策”可继续使用；本轮未改动项目名或源码。

近期建议按以下顺序推进：

1. 固定 Harness、MCP SDK、pymatgen 和首模型版本，完成当前首模型的独立任务服务。
2. 对 Chemeleon 和 CrystalFormer 各做一个最小真实任务，按可运行性、语义差异、产物质量和适配成本选择第二模型。记录失败，不用模拟输出替代。
3. 按展示和证据需求，选择性接入官方 MP 查询与 3Dmol；避免与第二模型、队列验收同时扩展大量功能。
4. 冻结任务书规定的 A/B/C 对照条件，再评估智能体收益。对外说明引用的模型、框架和工具，以及 MatPilot 自己实现的规则与验证。

本调研提出的选型建议均待接入验证。当前没有足够证据给出可节省多少工时、生成质量提高多少或获奖概率等数值。
